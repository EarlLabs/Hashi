# hashi — decision journal

<!--
WHAT: One line per decision that the NEXT run has to know about. Read first,
      appended to last, by every persona this project consults.
WHY:  a persona has no memory between runs. Without this, every question starts
      from zero and the owner repeats context they gave an hour ago. The
      short-term half of memory (the last N exchanges) lives in the Warden's
      state volume and is deliberately forgettable; THIS half is durable — it
      survives rebuilds, quota resets and container wipes, and the owner can
      read and correct it.
HOW:  append at the bottom. Never rewrite a line: a decision that was reversed
      gets a NEW line saying so, because "we changed our mind in March" is
      itself the thing a later run needs to know.
-->

**The test for whether a line belongs here:** *if the next run does not know
this, will it decide wrongly?* If no, it is not a decision — it is progress, and
progress belongs in the task's own files.

Good: "chose Postgres over SQLite — the fleet writes concurrently and SQLite
locks." Bad: "implemented the login screen."

| 2026-09-09 | **Decision 3 — when the hop is down, an entry node fails CLOSED.** A friend connected to an entry node whose hop to its leaf is unavailable gets **no exit at all**, never a local one. | The owner's answer of 2026-09-08, implemented in M3. Every visible signal stays green while the exact protection the two-node topology exists to provide is gone. | 2026-09-09 | **The entry node's hop-peer `AllowedIPs` is `0.0.0.0/0`, deliberately.** The control plane's own SSH is protected by a *different* mechanism: `Table = off` on the entry's hop config, plus a source-based `ip rule` for the tunnel's own address into a dedicated table. **Do not re-narrow it** — `docs/PLAN.md`'s M3 prose still describes the old narrow value and now carries a correction beside it. | Discovered implementing M3. `AllowedIPs` is not a firewall list, it is WireGuard's crypto-routing table: a packet is only encrypted to a peer whose `AllowedIPs` covers its **destination**, and a reply is only accepted if its **source** is covered. Return traffic from a relay arrives sourced from the *internet host the friend asked for*, not from the leaf — so a `/32` entry can send nothing but pings to its own peer, and the relay cannot work at all. What made a wide list frightening was the route `wg-quick` derives from it, and that is a separate switch. Verified on the live fleet: with `Table = off` the main routing table still reads `default via <gateway> dev eth0`, only source-routed traffic from the tunnel address enters the hop, and the SSH session the control plane manages the node over survived the apply. |

| 2026-09-09 | **`default_sni` is set to the private (console) host, not the public one** — accepting that a client which sends no SNI to `:443` is answered with the console's certificate and thereby learns the console's tunnel address. | Forced by a field defect: a TLS client sends **no SNI when the host is an IP literal**, and a WireGuard tunnel hands you an address. With several certificates and no name to look up, Caddy cannot choose one and aborts — so the console was unreachable by every route, and the public site had the identical defect, meaning `/sub/{token}` was equally dead for any client dialling an address. `default_sni` is **global**: Caddy has no per-site form and `tls internal { default_sni … }` is rejected by the adapter at 2.8.4, which was tried. So one value serves both listeners and the two choices trade differently. Setting it to the **public** host means the owner gets `ERR_CERT_COMMON_NAME_INVALID` on **every** visit to their own console, forever; setting it to the **private** host discloses an RFC1918 address that nobody can route to. Leaking an unroutable address is a smaller harm than training the single operator to click through TLS warnings on the one surface that must never be impersonated — a habit that survives the day someone does impersonate it. The escape hatch is documented rather than recommended: an owner who can resolve a name on every device may put a name in `HASHI_PRIVATE_HOST` and pays neither cost. |
| 2026-09-09 | **`HASHI_PRIVATE_HOST` is an IP, deliberately, and `HASHI_PUBLIC_HOST` must be a name.** | The private side settles on the **phone**, not on the tunnel: a hosts entry cannot be added to one without root, and the phone is the device reached for during an emergency rotation. A name there would need DNS inside the tunnel, and this project has already deliberately refused to hand a host's resolver to a tunnel. So an IP is the supported shape and `default_sni` is what makes it work. The public side runs the other way and is now stated beside the value in `.env.example` and the runbook: **a public CA will not issue for a bare IP**, so Caddy falls back to its own CA and every stock client refuses the certificate — `/sub/{token}` fails for every friend while nothing on the host looks wrong. `default_sni` gets a handshake to complete; it cannot manufacture trust, and that improvement must not be read as "an IP is fine now". Nothing yet refuses an address in `HASHI_PUBLIC_HOST` at boot; that would be a `control` change and is recorded rather than done. |

| 2026-09-09 | **The test for whether a cell belongs on a screen: does it move when a friend *connects*?** If it moves only when the **operator** acts — mints a credential, revokes one, changes what a node serves — it is a fact about our own configuration and it may be shown. If it moves because a person *used* the service, it is an analytic about them and it may not exist at all. Applied to keep the Users table's `nodes served` (`3 / 3`) count, which decision 6 did not enumerate. | Raised by M8's implementer, who flagged it rather than resolving it silently, and ruled on by its reviewer. The reasoning, worth keeping because it will be needed again on every screen M9 and M10 add: `nodes served` counts credentials **we minted** against node-transports **currently serving**. It needs no new stored data, has no temporal or behavioural component, and — the decisive part — **seizing the database yields the identical number whether the cell exists or not**. That is the charter's actual test: *"absent, so there is nothing to seize or subpoena."* A cell that only re-presents what the operator already put there adds nothing to seize. Contrast the four cells decision 6 removed: "throughput now", "last seen", node "load" and the Traffic screen each required the product to **observe a person** and keep the result. Note the tension this leaves, deliberately: M8's own "done when" says *"no screen shows a per-user number anywhere"*, and by the letter this is one. | 2026-09-09 | **The console opts out of htmx's history cache (`hx-history="false"`), and every panel response is `Cache-Control: no-store` with `Vary: HX-Request`.** | Found by chasing an acceptance finding, and the cause was not where anyone looked first. A console URL has **two representations**: the whole document a browser navigates to, and the fragment htmx fetches with `HX-Request: true`. Panel responses carried no cache directive and no `Vary`, so the browser stored the **fragment** under the page's own URL — and a back/forward navigation reuses a stored entry *without revalidating*, rendering a fragment that has no `<head>` as the entire document. That is why the console came back unstyled, why it stayed that way, and why only a reload fixed it: a reload re-requests without `HX-Request`. **It needed a boosted navigation first**, which is exactly why no fresh-load test could see it. Two neighbours of the same family came out with it, and the second is the one that matters: htmx's history cache writes the **whole body to `localStorage`**, and after the add-user flow that body contains the open dialog holding a **live subscription URL** — a bearer credential in precisely the place this project forbids, "anything a browser would remember". The cost of `hx-history="false"` is that Back now costs one request instead of a local read, which is the right trade for a console whose links are credentials. |
