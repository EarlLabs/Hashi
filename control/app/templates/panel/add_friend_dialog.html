{# "Add a user" — the panel's one global creation flow. UI-PATTERNS §5: creation happens in a dialog, never inline on the page, and the dialog is title → fields → one sentence on the consequence → actions with cancel secondary and confirm primary, right-aligned. The opaque background is not decoration: the design system's `.dialog` is TRANSPARENT (styles.css's blueprint layer resets it), so `background: var(--color-bg)` in app.css is what stops the page showing through the text. Re-rendered with `error` set when the nickname is refused, so the message lands under the field it is about — M8.6. A toast would be wrong here: it disappears after 2200ms and leaves the operator looking at a form that will not submit. NO `maxlength`. It was here, and it made the field lie: a pasted 1002-character name became 64 characters in the box with no counter, no message and no hint that anything had been dropped, and the person was then created under the clipped name as though that were what the operator typed. The limit is now STATED under the field and ENFORCED by services/friends.py, which refuses over-long input with a sentence through the same 422 path as a duplicate name. Both halves matter: the hint means the operator rarely meets the refusal, the refusal means they are never silently given something other than what they asked for. NO FORM AT ALL WHEN A POOL IS FULL — M17.2. A user is given an address on every serving transport that hands out one, so a pool with no room refuses every submission of this form rather than some of them. The dialog asks the same question the service asks (services/console.py's `full_pools`, which is `addresses.shortfalls(extra=1)`) and draws no submit button when the answer is not empty — the same shape the transports dialog uses when there is nothing left to enable, and the state dialog uses on a retired node. Every full pool is NAMED, because "no room" without a pool to go and resize is a dead end; nothing about any person is named, because a count is all this knows. In that branch the service's own refusal sentence is NOT also printed. It is reachable — an operator submitting this form the moment a pool fills gets it at 422 — and it says the same three facts in the code's own vocabulary, under a field it is not about. What they read instead is this dialog, which is the same answer composed for the screen. #}
