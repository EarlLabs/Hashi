{# Nodes — the machines that serve traffic and the machines that exit it. The first of M9's fleet screens. The layout is design/README.md §3: the screen's own "add node" secondary above a full-width table of name / exit / address / state / transports / actions. Two departures, both deliberate: * the design's node "load" is not here and never will be. It is one of the four cells docs/decisions.md removed — a node's load is a measurement of the people on it. The `config` column stands in its place, reading drift against the digest we last applied, which answers "is this node running what I told it to". Same test as every other cell on every other screen: does it move when a friend CONNECTS? This one moves only when the operator acts. * a degraded node's reason gets its own row under it. The design never drew one, and an unexplained degraded node is a node nobody fixes. The pre-redesign page at /panel/fleet still owns hops, the transports table, and the per-node actions this screen does not carry yet — enabling and withdrawing a transport, moving a node between states, rotating keys. M9.5 retires it once all of those have a home; until then it is reachable from the sidebar and says what it is. #} {% include "panel/console_header.html" %}

A node reaches nobody until a protocol is enabled on it, its configuration is applied to the host, and it is put into service. Users hold one link covering whichever nodes are serving at the moment they refresh, so adding or replacing one asks nothing of them.
