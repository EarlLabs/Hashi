## From M38.1 (`/nodes`, and the add's reply offers `/apply`) — commit 8e9b28c, review clean in round 1

- **`/nodes`** is a `_COMMANDS` entry (`_nodes`, argument ignored). It reads `console.nodes_missing_what_they_would_be_given(session)` only — never the probe, no network — and replies through `_messages` with one block per behind node: the console's `NOT_PUSHED` sentence filled for that one node, then `APPLY_IT = "apply it: /apply {name}"`. Empty list → `NOTHING_BEHIND = "Every serving node holds the configuration it would be given."` (the e2e asserts this literal on a fresh stand).
- **Node naming.** A node is named by its `name`, unquoted, verbatim (names may hold spaces, max 64) — never its id or address. `/apply` must take its whole argument as the name.
- **The add's reply** when a node could not be updated: links, then `AddOutcome.headline()` (the summary's unchanged opening `"<n> user(s) added and pushed to <k> node(s), but <m> node(s) could NOT be updated and do not know them yet:"`), then per failed node `onboarding.why_not_reached(kind, name=name)` + `APPLY_IT`; nodes the add reached get no offer; "no node is serving" still appends `summary()`. `AddOutcome.summary()` was split into `headline()` + `ReachOutcome.not_updated()` (`[(name, kind)]` sorted by name) with byte-identical output.
- **USAGE** now: `/adduser <nickname> — one nickname per line — adds them, pushes them to every serving node and replies with their links. /nodes — which serving nodes are behind what would be pushed, with the /apply for each. /apply <name> — the Nodes screen's Apply, for that one node. Everything else is on the panel.` A test asserts every `_COMMANDS` key appears in it, so registering `/apply` needs no USAGE change.
- **Helpers:** `_not_updated_block(name, kind)`, `_behind_block(node: console.BehindNode)` (formats `console.NOT_PUSHED` with singular fillers; if that template gains a placeholder this call site follows). Test harness: `a_node_left_behind(client, hosts_down, address=...)`; the node-name no-leak pattern in `test_a_node_that_is_behind_is_named_in_the_reply_and_in_no_log_record`; `"a stranger's /nodes"` in `STRANGERS` — add `/apply` the same way.
- **e2e:** `test_nodes_answers_what_the_nodes_screens_block_says` compares the names after `apply it: /apply ` with the Nodes screen's `Apply <name>` buttons (`GET /panel/nodes/table`); keep it last in the file.

## From M38.2 (`/apply <name>`) — commit c9aeb92, review clean in round 1

- **Dispatch.** `/apply` is a `_COMMANDS` entry; the whole argument, trimmed, is the node's name, resolved exactly through `relocation.node_by_name` (the CLI's lookup); its own `no node named '<name>'` sentence is the refusal, nothing dialled. Bare `/apply` (and `/apply@bot`) → usage.
- **Which apply.** `apply.apply_node(session, node_id=...)` with the serving-only guard OFF — the Nodes screen's button and the API's `POST /api/nodes/{id}/apply`, which take a draft or degraded node into service. A test pins state, `state_detail`, probe columns and the trail (compared by CONTENT — an apply's two entries share a timestamp) equal to the API's apply.
- **Replies, verbatim for the runbook.** Ack `applying <name> — about a minute` (`APPLYING`). Success `console.applied_toast` → `config applied to <name> — <config names>` (plus a restarted clause when one was). Unmeasured: `console.applied_unmeasured` (singular form) — config names only, never content. Refusal/failure: the API envelope's sentence verbatim (nothing-to-apply, retired, unreached), pinned by equality with the API's own 409/502 bodies; NO panel-pointer sentence under apply refusals. The one exception: a checker refusal (`ConfigRefused`), whose envelope sentence can quote the checker's output, is answered from its kind and name via `onboarding.why_not_reached(apply.why_not_updated(exc), name=...)` → `'<name>' could not be given a configuration: it was refused before anything was pushed, and retrying will not change that — apply it from the Nodes screen to read why`. Non-domain failure: `applying <name> did not complete — the Nodes screen shows the state it was left in; what failed is in the control plane's log.` (`APPLY_DID_NOT_COMPLETE`, sent best-effort) and the exception re-raised for the poller to log by type.
- **Divergences recorded in the module:** `/apply` answers a non-domain failure with a fixed sentence then re-raises, where `/adduser` answers nothing; the post-apply result reply is not guarded against `TelegramCallFailed` (the apply's own log line precedes the poller's "not handled" line — read together).
- **Test harness:** `a_node`, `a_node_with_a_transport` (draft), `a_serving_node`, `the_node(client, id)`, `trail_for(session, name)` (sorted by content), `fragments(secret)`, `MARKER`; an unmeasured apply = `monkeypatch.setattr(listening, "bound_ports", …)` after `hosts_down`; a checker-refusal premise is asserted on the API envelope first, and the reply is checked with `pytest.fail` and fixed labels so a failure never prints sensitive text.
- **e2e:** `/apply <unknown>` refused in words, placed before the `/nodes` test, which stays last.
